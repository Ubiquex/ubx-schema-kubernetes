# CLAUDE.md — ubx-schema-kubernetes

## What this is

The real, published schema snapshot for the Kubernetes provider — a frozen,
versioned `manifest.json` + `members/*.json` group, generated by
`ubx-provider-dynamic --generate-snapshot-group` from Kubernetes' own live
`release-1.37` OpenAPI/Swagger description, committed here (not release-only)
so a reviewer sees the real diff. A `[providers.kubernetes]` pin in `ubx`
resolves against this repo's own real GitHub Releases via
`provider.AcquireSchema`. Coordinating repo: `github.com/ubiquex/ubiquex`.

Two real members in this group: `kubernetes` (resource mode) and
`kubernetes_ds` (data-source mode) — both come from the identical fetch, one
pin resolves both.

## Session protocol

1. Read `STATE.md` first — current state only, rewritten not appended.
2. `STATE.md` is rewritten, not appended, as the LAST act of every session.
   Anything that becomes history moves to `HISTORY.md`.
3. Only reference Linear issue IDs given in the handoff prompt; never infer
   one.

## Git rules (strict)

- PR-only. Never self-merge — push a branch, open a PR, wait for the founder.
- Before pushing more commits to a branch with an open PR, confirm it is
  STILL open (`gh pr list --state open` or `gh pr view <n>`) — a merged PR's
  branch looks identical to any other from `git status` alone, and a push
  after merge lands nowhere near `main`, silently.
- NO AI attribution anywhere in commits or PR bodies.

## Repo-specific mechanics

- `.github/workflows/hash-watch.yml` — weekly cron + manual dispatch. Builds
  `ubx-provider-dynamic` from ITS OWN real, latest published release tag (not
  `main` HEAD — building an untagged HEAD stamps every regenerated snapshot
  with the meaningless `min_binary_version: "dev"`, UBI-194), regenerates,
  opens a PR only when the group's own mechanically-derived version actually
  moves. Never auto-merges.
- `.github/workflows/publish.yml` — manual dispatch only. Refuses to
  republish an existing tag. Cuts `snapshot.tar.gz` + `SHA256SUMS` against the
  version already committed in `manifest.json` — verify with `gh api
  repos/Ubiquex/ubx-schema-kubernetes/releases/tags/v<version>` after
  dispatch, not the workflow's own exit status.
- A version bump here does not always mean the live Kubernetes API changed —
  `AssembleGroup` also forces at least a Patch bump when only
  `min_binary_version` changed and no member's own content did (confirmed
  live: `v3.0.0 -> v3.0.1` carried zero real API drift).
